# 05 — UI/UX, Aksesibilitas, Performa

Metode: v1 di-build (`next build`) dan dijalankan lokal terhadap Supabase lokal berisi skema v1 (tanpa whitelist email), lalu ditelusuri
dengan Playwright (Chromium) pada **390×844 (mobile, touch)** dan **1280×800 (desktop)**, locale `id-ID`, zona `Asia/Jakarta`.
Alur: login → dashboard kosong → tambah 3 dompet (operasional/tabungan/kantor) → catat pengeluaran (quick add) → transfer →
buat anggaran → catat utang + cicilan 50% → buat tujuan tabungan → buka laporan dan halaman lain.
Setiap halaman diperiksa dengan axe-core 4.10.2 (WCAG 2A/2AA/2.2AA), jumlah elemen interaktif < 44px, dan CLS.
Screenshot: [`screenshots/v1/`](screenshots/v1/) (`mobile-*.png`, `desktop-*.png`), data mentah: [`screenshots/v1/report.json`](screenshots/v1/report.json).
Skrip walkthrough tidak disimpan di repo karena berisi kredensial akun uji lokal; langkahnya tercantum di atas.

Catatan: "sebelum/sesudah" — screenshot "sesudah" (v2) akan ditambahkan di Fase 3 dengan alur dan viewport yang sama.

## 2. Pola input

- **Mencatat pengeluaran:** tombol "+" (FAB) hanya ada di `/transactions` (`transactions/page.tsx:973-981`). Dari Beranda: ketuk "Transaksi" (1) → FAB (2) → ketik nominal (keypad) → buka & pilih kategori (3–4) → "Catat Pengeluaran" (5). Jika kategori punya subkategori: +1. Terukur 4 ketukan dari halaman Transaksi, **5–6 dari Beranda** (`report.json flows.quickAddTapsFromTransactions`). Dompet default = dompet non-kantor pertama, bukan yang terakhir dipakai. Tidak ada saran kategori terakhir/umum.
- Nominal memakai `<input type="number">`: tanpa pemisah ribuan saat mengetik ("25000"), menerima `e`, desimal, dan negatif (`-50000` lolos dan menghapus transaksi saat edit, 02-integrity INT-02).
- Form lengkap: 8–10 field dalam modal; dompet berupa `<select>` campur kantor/pribadi dengan emoji sebagai pembeda.
- Validasi hanya lewat toast (`toast('Lengkapi data!', '⚠️')`) — tidak menandai field mana yang salah; tombol simpan tidak dinonaktifkan saat menyimpan (double-submit, INT-18).
- `window.confirm()` 16× untuk hapus/peringatan (mis. "Saldo … tidak cukup … Lanjutkan?" saat transfer, terekam di `report.json flows.dialogs`); hapus anggaran **tanpa** konfirmasi sama sekali (`budgets/page.tsx:116-119`). Tidak ada undo.
- Pesan konfirmasi tidak menjelaskan akibat uang (mis. hapus utang membalik semua cicilan tetapi pesan hanya "Hapus catatan ini?" `debts/page.tsx:326`).
- Toast sukses muncul meski langkah kedua gagal (CQ-03). Toast menutupi bottom nav di mobile (`mobile-transactions.png`).
- Aksi edit/hapus muncul hanya saat hover (`opacity-0 group-hover`, 12×) → **tidak terlihat di layar sentuh** (dompet, transfer, anggaran, aset, riwayat goal). Di mobile user harus menebak bahwa ikon kartu bisa diketuk.
- Quick add sheet `z-50` tumpang tindih dengan bottom nav (`mobile-quickadd.png`).

## 3. Empty, loading, error state

- Empty state ada (teks + emoji) tetapi tanpa ajakan langkah pertama di dashboard (`mobile-dashboard-empty.png`: "Rp 0" di 5 kartu, "UTANG -Rp 0" merah, "FREE CASHFLOW +Rp 0" hijau).
- Skeleton hanya di dashboard, transfers, savings-goals, trips; halaman lain kosong lalu "melompat". Error load tidak dibedakan dari data kosong (CQ-03).
- AppShell menampilkan spinner layar penuh sampai `getSession` selesai di setiap navigasi.

## 4. Aksesibilitas (axe-core)

| Pelanggaran | Mobile (node) | Desktop (node) | Halaman |
|---|---|---|---|
| `color-contrast` (serious) | 233 total | 215 total | semua; terbanyak `reports` (41) |
| `button-name` (critical) | 2 | 3 | transactions, debts (tombol ikon ✏️/✕/○ tanpa label) |
| `select-name` (critical) | 5 | 5 | reports, export, ai-analysis |
| `label` (critical) | 2 | 2 | export |
| `scrollable-region-focusable` | — | 1 | dashboard |

- Kontras: `text-surface-400` (#94a3b8) di putih = **2,56:1**, `text-surface-300` (#cbd5e1) = **1,48:1** (AA butuh 4,5:1). Dipakai untuk label, tanggal, placeholder, dan teks empty state. `text-surface-500` (#64748b) = 4,76:1 lulus.
- 124 `<label>` tanpa `htmlFor`; input tidak terhubung ke labelnya (axe tidak selalu menandai karena placeholder dianggap nama).
- Tap target < 44px: hingga 25/50 elemen di Kategori, 16/36 di Dompet desktop, 9/35 di Dompet mobile (ikon ✏️/✕ 28px `w-7 h-7`, chip tanggal `text-[10px] px-2 py-1`).
- Teks 9–10px (`text-[9px]`, `text-[10px]`) dipakai luas untuk informasi penting (tanggal, saldo trading, peringatan shortfall).
- Modal tanpa `role="dialog"`, focus trap, Escape, atau pengembalian fokus (`components/Modal.tsx`); toggle custom (reimburse, aktif) adalah `<button>` tanpa `aria-pressed`.
- Emoji sebagai satu-satunya ikon/penanda (pocket, tipe dompet, status reimburse ✓/○) — dibacakan pembaca layar sebagai nama emoji atau tidak bermakna.
- Tidak ada dark mode (0 kelas `dark:`), padahal body memakai warna terang tetap.
- Warna sebagai satu-satunya pembeda pemasukan/pengeluaran di beberapa daftar (hijau/merah + tanda +/− membantu sebagian).

## 5. Format angka dan tanggal

- Tiga format nominal bercampur: `formatCurrency` ("Rp 1.250.000"), `formatShort` ("Rp 1.3jt", membulatkan ke atas dan memakai titik desimal gaya Inggris), dan `Intl compact` ("Rp 25 rb") di halaman yang sama (`mobile-transactions.png`, `desktop-debts.png`).
- `formatShort` memakai "M" untuk miliar (umum di ID: "M" = miliar, tetapi "jt" vs "rb" huruf kecil) dan `toFixed(1)` → "1.3jt" bukan "1,3 jt".
- Tanggal selalu absolut ("29 Okt 2026"); tidak ada "Hari ini/Kemarin"; tanggal default bisa salah 1 hari sebelum 07:00 WIB (INT-07).

## 7. Kesimpulan UX

v1 fungsional dan konsisten secara visual pada tingkat kartu, tetapi:
1. Pencatatan harian (aksi paling sering) butuh 5–6 ketukan dan tidak tersedia dari Beranda.
2. Banyak aksi tidak terlihat di layar sentuh (hover-only) padahal mayoritas penggunaan diduga di HP.
3. Kontras dan ukuran teks kecil gagal WCAG AA secara sistemik — perbaikan harus di level token, bukan per halaman.
4. Konfirmasi/umpan balik tidak menjelaskan akibat uang, dan sukses bisa dilaporkan saat sebagian gagal.
5. Beranda tidak menjawab "berapa yang aman dipakai?" — angka "Bisa dipakai" = total saldo operasional, tidak dikurangi tagihan mendatang/anggaran tersisa.
